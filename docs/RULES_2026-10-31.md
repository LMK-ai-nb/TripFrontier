## 建议做到（不冒充硬性条款）

- `--deny-warn`、格式、公开 API 文件核对；独立 oracle 对照，真实 CLI 与浏览器运行。
- 多后端、多操作系统 CI；对真实、经授权的数据进行集成验证；明确规模和未支持语义。
- 先让参赛者实际运行和解释三个场景，再独立写一页申报书，陈述实际贡献和相邻项目。

## 仍待确认或存在口径差异

- 用户明确确认本轮可提交且今晚 24:00 截止，工作按此安排。官网列出 10-31，但未在已读页面明确小时；所链章程虽然显示 10-30 更新，流程仍保留 9-30 的日期，不能把它直接当十月截止时间。具体执行以赛事群/工作人员通知为准。
- 当前表单是“三次提交，可重复修改”，并不单独证明“三个独立项目名额”。章程 3.2 还写原则上一位参赛者一个项目；用户提供的口径与此存在差异，资格最终由组委会认定。本轮依用户确认继续开发，不据此声称报名资格已审核通过。
- 更换 GitHub 账号、旧提交与新账号的贡献对应、剩余提交次数的计数方式，已读官方内容没有给出完整处理规则；须如实披露并由组委会确认，不通过换账号规避历史。
- 表单有“查看提交记录”入口；实际可修改记录和登录权限尚未检查，未代操作用户报名记录。
