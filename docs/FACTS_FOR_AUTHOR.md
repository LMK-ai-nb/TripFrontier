# 项目事实核对清单（AI 辅助整理）

本文件是项目事实索引。依据李明坤反馈的工作人员答复，本次允许 AI 辅助准备申报书；正式材料由李明坤复核并提交，联系电话/邮箱不放在公开仓库。

- 项目名：TripFrontier；定位：离线时刻表乘客行程规划内核；属于数据处理/可复用基础库。
- 目标用户：园区班车、公交铁路信息、离线出行应用开发者；尚无实际客户采用证据。
- 本地路径：D:\CodexProjects\TripFrontier；新目录和独立根提交，与旧项目不共用业务实现。
- 账号：LMK-ai-nb；维护者/参赛者：李明坤，个人参赛。GitHub/Mooncakes 均核实。初始未公开本地草稿绑定身份的过程见 AUTHORSHIP.md。
- 核心 MoonBit：Timetable、Query、三维 Pareto 标签搜索、精确班次见证、可行性核验、取消/延误/关闭路径重算、严格 JSON。
- Python 仅导入文档化 GTFS 子集，Node 仅文件/启动适配，网页仅展示和交互，不调用外部路线 API。
- 成立的差异：静态步行图不能直接表达发车时刻、同车停站与换乘；ATS 调度与乘客多目标搜索的用户及输出不同。相邻性仍须披露。
- 三个完整用例的输入/操作/结果/验证见 SCENARIOS.md；不得把合成样例写成实际部署。
- 独立对照：240 个小网络，穷举全部可行路线后筛选目标值，与 MoonBit 前沿逐例比较一致；有固定种子，代码和原始输出可复现。
- 其他证据：MoonBit 单元/可执行文档、CLI 集成、GTFS 导入、真实 Chromium、实际打包检查；精确结果和限制见 VALIDATION.md。
- 原创实现使用 AI 辅助；概念与成熟方案参考在 RESEARCH.md，MIT 许可证和标准库 NOTICE 已保留。
- 不支持：全国规模、完整GTFS、GTFS-RT、票价、多服务日联合、贯通车辆/频率/预约班次、真实道路推断、arrive-by/最晚离家、设施实际安全保证。
- 仓库、CI、Mooncakes 的真实发布证据以 RELEASE.md 为准；没有代提交报名或审核成功记录。
- 不应承诺：世界唯一、无任何竞争、算法发明、性能胜过成熟系统、已通过初审/验收/获奖。
